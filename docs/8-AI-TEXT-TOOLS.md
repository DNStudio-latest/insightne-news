# 8. AI text checker and style editor

A research tool with two parts:

1. **Checker:** gives a 0–100 score for how closely a text matches writing-style patterns associated with AI-generated text, and lists the signals behind the score.
2. **Style editor:** replaces plain filler phrases ("in order to" → "to") and lists other phrases and habits for you to review.

All the work happens in the reader's browser. No text is sent to the website, to Claude or to any other service. The page is at **`/ai-tools/`** on the website (for example `https://<your-domain>/ai-tools/`). It is hidden from search engines (`noindex`) and does not appear in the site menu.

## Read this first

- **A score is not proof.** Style-based detectors make mistakes. Formal academic prose and writing by non-native English speakers are flagged in error more often (Liang et al., 2023, "GPT detectors are biased against non-native English writers", *Patterns*). Never use a score alone as evidence against a person.
- **The built-in model is uncalibrated.** Its weights are hand-set starting values, not learned from data. For research results, train a model on your own labelled corpus (below) and report its cross-validated figures.
- **English only.** The phrase list and the contraction and first-person measures are for English. Bengali and Kokborok text is tokenised but not scored meaningfully.
- **The style editor does not hide AI use.** It improves clarity. If AI helped write a text, disclose that as your university or publisher requires.

## Use it on your PC (no internet, nothing to install)

Use the single-file version, `ai-text-checker.html`. Save it anywhere (for example, Documents) and double-click it to open it in Chrome, Edge or Firefox. It contains the whole tool, so it needs no Python, Node or web server.

To rebuild that file after changing `engine.js` or `index.html`, run:

```bash
node scripts/ai-text-standalone.js ai-text-checker.html
```

## Train a model on your own data (for research)

1. Make a CSV file with a header row `label,text`. Use one row per text. The label must be `ai` or `human` (or `1`/`0`). Put each text in double quotes. Texts of 150 words or more give steadier results.

   ```
   label,text
   human,"The first paragraph of a thesis chapter written in 2015…"
   ai,"A passage generated by a language model from the same prompt…"
   ```

   For a fair test, the two groups should cover the same topics and genres, and be roughly balanced. Otherwise the model learns topic differences instead of authorship.

2. Run:

   ```bash
   npm run ai-text-train -- my-corpus.csv --out my-model.json --name "Thesis corpus v1"
   ```

   The script prints the number of texts, the **5-fold cross-validated accuracy and AUC**, and the weight of each feature. It also saves `my-model.json`. AUC is the usual figure to report: 0.5 means chance and 1.0 means perfect separation. Options: `--folds 10`, `--l2 0.1` (more regularisation for small corpora).

3. On the `/ai-tools/` page, click **Use a trained model (.json)** and choose `my-model.json`. The page now scores with your model and shows its AUC.

Keep a held-out test set that the model never sees during training, and report that result as well. Cross-validation on one corpus overstates how well the model works on text from other sources or newer AI models.

## What the checker measures

| Feature | Meaning |
|---|---|
| Sentence length and its variation | AI text tends to have more even sentence lengths ("burstiness") |
| Word length, share of long words | Vocabulary weight |
| Vocabulary variety | Distinct words per 100-word window |
| Commas, semicolons/colons, dashes, exclamation marks | Punctuation habits, per 100 words |
| Contractions, first-person words | Informal and personal voice, per 100 words |
| Transition words | "however", "moreover", "furthermore" and similar, per 100 words |
| Stock AI-style phrases | "delve", "tapestry", "plays a crucial role" and others, per 1,000 words |
| Repeated sentence openings | Share of sentences that start with the same word |

The model is logistic regression on these standardised features. With a trained model, the weights show which features separate your two groups. You can report them in your thesis.

## Files

| File | What it is |
|---|---|
| `public/ai-tools/engine.js` | Features, scoring and style editor (one file, no dependencies) |
| `public/ai-tools/index.html` | The web page |
| `scripts/ai-text-train.js` | Training and cross-validation |
| `scripts/ai-text-standalone.js` | Builds the single-file version for use on a PC |
| `tests/ai-text.test.js` | Tests (`npm test`) |

To add or remove stock phrases, edit `AI_PHRASES` in `engine.js`. To add automatic replacements, edit `SAFE_REPLACEMENTS`. Only add a replacement if it can never change the meaning.
